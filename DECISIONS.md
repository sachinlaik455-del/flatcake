# DECISIONS.md — architectural decisions and rationale

| # | Decision | Rationale | Alternatives rejected | Source |
|---|---|---|---|---|
| D1 | Fidelity **Level B** (CPU prototype, real local SSD I/O); Level A only for algorithm unit tests; Level C design-only | Directive Part 2; hardware (16 GB laptop, no CUDA/GDS assumed) makes C impossible now; B keeps real I/O credibility | Jumping to C (hardware unavailable); pure simulator (would mislabel synthetic numbers as measurements) | Directive Part 2, Part 16 |
| D2 | Paper-reported numbers never presented as ours; qualitative mechanism comparison only | Different hardware, different trace; numeric comparison would be fabrication | Scaling paper numbers to laptop | Directive Part 23 |
| D3 | Synthetic workloads only; production trace NOT downloaded | License/size unverified; 16 GB machine; directive forbids inventing trace data | Downloading claude-code-weka-0621 (OQ-18) | Directive Part 11, Part 21 |
| D4 | Stack selection deferred to ENVIRONMENT_AUDIT.md evidence (Rust vs C++ for core; Python for analysis) — decided by toolchain audit, not preference | Directive Part 3 requires audit before selection | — | Part 3 |
| D5 | τ=4096 tokens, L_agent=65536 tokens as defaults | Grounded in paper's footprint math (7.5 KiB/token/rank FP8): 4096-token reply ≈ 30 MiB/rank (small, DRAM-worthy); 65536-token context ≈ 0.5 GiB/rank ≈ Claude Code median | Arbitrary other values | OQ-1, OQ-2 |
| D6 | HRRN priority recomputed at dispatch decisions (lazy), not continuously | Eq. 1 semantics + avoids background resort; documented as reference interpretation | Continuous reorder (unspecified in paper) | OQ-4 |
| D7 | Scope→GPU File: contiguous file chain when session exceeds one pre-allocated file | Paper implies 1 file/scope but gives no size bound for multi-GiB sessions; chaining preserves contiguity per file and is reversible | Unbounded single files (defeats pre-allocation) | OQ-11 |
| D8 | Max 2 concurrent implementation agents; component agents (FC-GVA/FC-MAS/FC-CIO/Testing/Benchmark) with strict file ownership | Directive Part 18 | Full parallel fan-out | Part 18 |
| D9 | EGM plugin personas used at gates: architecture review (M2), audit support (M12) | User instruction "use egm plugins"; fits persona design | Running EGM on every commit (waste) | User directive |
| D11 | **Open-loop replay driver** (issue at ts_us×time_scale, in-flight cap, arrival_ts = intended) | EGM M2 critical: closed-loop blocking clients cap queue occupancy at #clients and erase every FC-MAS phenomenon the benchmarks exist to show | Blocking clients (kept for demo only) | EGM review |
| D12 | **FILE_FLAG_NO_BUFFERING on all scope-file I/O**, both systems | Without it Windows page cache makes every `measured:` SSD number a cache artifact and cross-system run order contaminates fairness | Buffered I/O (rejected: fabricated measurements) | EGM review |
| D13 | Index: fixed capacity, states EMPTY/PENDING/PUBLISHED/TOMBSTONE, CAS-loser re-probes, no resize (startup asserts ≤0.7 load) | EGM M2: PENDING rollback + reclaim invalidation break probe chains without TOMBSTONE; concurrent resize needs epoch design unjustified at our scale | Resizable lock-free table (over-engineering) | EGM review, OQ-16 |
| D14 | Frozen placement precedence: refcount>1→DRAM, ctx≥L_agent→SSD, reply≥τ→SSD, turn=1→SSD, turn>1∧reply<τ→DRAM; SSD-scope appends sticky, DRAM-scope appends re-evaluated; DRAM-full spill flips scope to SSD | Paper Table 2 has no precedence and genuinely conflicts under stickiness; asymmetric-cost argument makes SSD-stuck chats acceptable | Silent ad-hoc choices per implementer | EGM review, OQ-19 |
| D15 | Reclamation protocol: reader refs at resolve-time held to I/O completion, writer refs during PENDING, tombstone-invalidate index BEFORE freeing extent, O(1) = zero payload ops (instrumented assert) | EGM M2 critical: three race windows (stale GVA wrong-data, resolve→read TOCTOU, in-flight writer into freed extent) | Simple "never free referenced" (insufficient) | EGM review |
| D16 | Symmetric miss model: recompute cost + re-persist identical both systems; PENDING = miss by design; per-block hit accounting | EGM M2: asymmetric misses would rig the headline comparison | FlatCake-miss-free modeling (rigged) | EGM review |
| D17 | **One canonical workload generator: Rust `fckv gen-workload`**; Python does plots only | Payload byte pattern exists only in Rust → generator/verifier cannot drift; dual generators risk silent trace divergence | Python generator (cross-language byte-pattern risk) | EGM review |
| D18 | hbm window: byte-resident global 64 MiB LRU-by-delivery owned by engine.rs, identical both systems, checked per-block before classification | EGM M2: metadata-only window would fabricate hbm hits; asymmetric policy would rig HBM attribution | Metadata-only window | EGM review |
| D19 | Recovery log cut from scope | No traceability row exercises recovery; unbounded growth + write-ordering hazard | Implementing it (over-engineering) | EGM review, OQ-9 |
| D20 | Multi-file chaining deferred; workload enforces session ≤ gpu_file_bytes (asserted) | Dead code at prototype densities (32 B/token → sessions ≪ 256 MiB files) | Implementing unused paths | EGM review, OQ-11 |
